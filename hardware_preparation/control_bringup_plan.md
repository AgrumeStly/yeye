# 主控硬件到齐后的实施步骤

制定日期：2026-10-14。主责：主控；接线与供电由硬件协作，路径与命令通信由视觉协作。

## 当前起点

- 主控已确认负责采购的硬件到齐；不据此认定电机、底盘、供电和视觉模块已完成验收。
- 现有工程目标为立创天空星 STM32F407VET6 青春版，采用 SPL，工程位于 `control/firmware/yeye_control.uvprojx`。到货实物仍需核对版本。
- 根据既有验证记录，LogicDemo、HardwareBench 和 UART 开启分支已通过电脑端编译，通信及状态机通过55项电脑检查；这些是2026-10-12的历史记录，本次未重新编译或做实物测试。
- HardwareBench 当前使用 HSI 16 MHz、1 ms滴答和约5 ms调度。UART默认关闭，电机输出仅更新调试变量。
- 电机PWM、编码器、速度闭环、一圈判定和动作反馈尚未实现。现有左右请求数值是软件演示值，不能直接当作已标定的轮速或实车参数。

主线：实物与供电核对 → 下载运行 → 串口模拟包 → 电机开环 → 编码器 → 速度闭环 → 视觉循迹 → 故障停车 → 语音与终点。

## 第1步：确认实物与接线条件（预计半天）

主控：
1. 核对主控板型号、板卡版本、下载器型号和USB线；拍摄板卡正反面及接口标识。
2. 对照实际板卡说明确认供电入口、SWD接口和排针位置。不能只按芯片引脚名猜排针序号。
3. 与硬件记录电机驱动实际型号、编码器供电与输出电平、电池与稳压输出、共地关系和断电方式。
4. 将控制信号写成接线表：功能、MCU端口、板上接口、对端接口、电平、供电来源、负责人。

硬件：断电检查极性和短路，按实际模块说明逐路核对供电，复核USB与外部电源同时连接的条件。

验收：主控板身份明确；供电和调试连接有依据；候选引脚经实物复核。电机相关资料未齐时，主控继续第2、3步，电机暂不上电。

交付：实物照片、接线表和供电检查记录，保存在 `hardware_preparation/`。

## 第2步：把已有工程真正下载到板上（预计半天）

主控：
1. 按 `control/docs/keil_quickstart.md` 检查Keil、Compiler 5、芯片包和下载器设置。
2. 暂不接电机供电，按实物说明连接SWDIO、SWCLK、GND及所需目标参考电压/供电接口。
3. 打开现有工程，选择 **HardwareBench**，F7编译。LogicDemo只用于模拟演示。
4. 检查SWD连接及STM32F4xx 512KB下载算法，下载并运行程序。
5. 在Watch中观察 `g_control_ticks`、`g_car`、`board_left_request`、`board_right_request`；观察滴答和调度在运行后继续增长。
6. 复位并重新上电，确认保持IDLE、左右请求均为0。需要观察计数时运行一段时间再暂停，暂停期间计数不增长是正常现象。

验收：可以重复下载、运行和复位；没有异常复位；初始状态正确。

交付：下载设置与Watch截图，记录板卡、工程版本和验证日期。至此只说明程序在板上运行，尚未说明能控制电机。

## 第3步：先用模拟包打通串口（预计半天至1天）

主控与视觉共同确认 `control/docs/protocol_v1_draft.md`：波特率、20字节布局、单位、正负号、序号、CRC、发送频率和超时条件。协议目前仍为草案。

主控：
1. 与硬件核对USART2候选PA2/PA3是否可用，以及实际通信电平、交叉收发和共地。
2. 核对通过后，将 `board.h` 的 `BOARD_UART_ENABLE` 设为1，重新编译下载。
3. 使用确认兼容的USB串口工具或视觉板发送二进制测试包；若没有USB串口工具，可由视觉先发送固定包，不必等待图像算法完成。
4. 参考 `control/tools/protocol_example.py` 生成包。该脚本只生成十六进制和文件，不自动发送串口；串口工具应按HEX字节发送，不能发送字符文本“A5 5A”。
5. 连续发送新序号有效路径，再发送START，检查进入RUNNING；发送STOP，检查输出清零。
6. 测试仅有START、无效路径、停止发送路径、错误CRC、重复序号、恢复路径但没有新START。

验收：有效路径与START共同满足条件才运行；STOP生效；超时或无效路径触发停止请求；恢复数据不会自行重启。

注意：现有200 ms阈值用于判断路径是否过期，5 ms调度及执行还会引入响应延迟；电机机械停稳时间需后续另测。现有STATUS只解析，没有状态回包。

交付：通信测试记录和共同确认后的协议。先保留电机断电，观察状态和请求变量即可。

## 第4步：实现电机开环控制（预计1天）

前置：硬件交付电机、驱动和供电接线，主控确认实际驱动器接口及输入真值表。历史采购方案是AT8236，不能据此直接确定当前模块针脚与制动行为。

主控：
1. 确认PWM所需通道、驱动控制方式、上电默认状态、滑行与制动方式，再冻结电机引脚。
2. 实现初始化、方向、占空比限制和停车接口；明确状态机停止请求如何传到实际驱动输出。
3. 使用独立、明确选择的台架测试入口，轮子悬空，先单轮、再双轮，以较低输出短时验证前进、停止和反向。
4. 记录左右轮前进对应方向、起转区间和异常；反向测试先停车，不直接大输出换向。
5. 检查上电、复位、停止命令时的真实输出。台架入口必须能主动退出或超时停止，不能留成上电自动转动程序。

验收：每个轮子可独立控制；停止命令能改变实际驱动输出并使轮子停下；重启无意外运动。记录滑行/制动方式及停稳表现。

交付：驱动代码、正式引脚表、悬空演示录像。所有新增应用代码按工作区规则写详细中文注释。

## 第5步：读取编码器并换算轮速（预计半天至1天）

主控：
1. 复核候选资源：左轮PA0/PA1、TIM2；右轮PB6/PB7、TIM4。此处仍是软件候选，实际接线以冻结后的表为准。
2. 先手动转轮，观察A/B计数；统一“车辆前进”为正，核对左右轮归属。
3. 测量并记录车轮转一圈对应的实际解码计数；区分电机轴/输出轴、减速比及解码倍频，不能直接把铭牌脉冲数当车轮一圈计数。
4. 在固定采样周期读取计数增量，处理计数器回绕；记录实际采样周期并换算转速。需要线速度时，再结合实测轮径换算并注明单位。
5. 低输出驱动单轮，核对方向、增量和速度变化；检查静止时是否出现异常跳数。

验收：前后方向符号正确，左右通道不混淆；一圈计数可复现；速度与实际转动趋势一致。

交付：编码器参数、轮径、采样周期和计数/速度记录。

## 第6步：完成左右轮速度闭环（预计1至2天）

主控：
1. 明确接口：目标轮速、实测轮速和PWM各用什么单位，替换现有演示请求的临时语义。
2. 先调单轮，使用小幅目标速度变化检查响应；再调另一轮，最后双轮同目标运行。
3. 先建立比例调节，再根据稳态误差加入积分；设置输出限幅、积分限制和目标速度变化限制。无需一开始就同时调整全部PID参数。
4. 固定闭环采样周期并验证实际执行间隔，避免长延时和阻塞日志干扰控制。
5. 停车或故障时清理闭环状态并优先执行停车，避免积分残留造成再次启动突跳。具体制动策略按驱动资料和实测确定。
6. 悬空通过后，在硬件协助下进行地面低速直行，记录目标/实测速度及偏差；区分控制误差和轮径、摩擦、装配差异。

验收：低速可稳定运行、目标变化可跟随、无持续明显振荡；地面能受控直行并停车。

交付：左右轮参数、速度日志及低速直行录像。进入视觉联调前保存一个可恢复版本。

## 第7步：接入视觉循迹（预计1至2天，按实测追加）

视觉：交付稳定更新的路径结果、有效标志、偏差符号、处理耗时及典型失败样本。

主控：
1. 先发送模拟的左偏/居中/右偏结果，确认左右目标轮速变化确实能产生正确转向。
2. 接入真实视觉包，先调低速直道，再缓弯，再锐角；每次只改一类参数。
3. 将路径偏差转换为左右目标轮速，交给速度闭环；建立弯道减速和转向限幅。
4. 记录通信间隔、端到端延迟、目标/实测轮速和车辆状态，定位偏差来自视觉、控制还是结构。
5. 以连续3次低速完整跑圈作为首版目标；这是队内建议门槛，尚未实际通过。

验收：纠偏方向正确，直道与弯道可重复通过，有完整跑圈及失败记录。

## 第8步：验证真实故障停车，并增加终点与语音（持续开展）

故障保护从电机驱动阶段开始验证；此阶段完成整条链路的复测，不能等到高速试跑才验证。

主控与视觉：先悬空，再在受控场地下低速测试通信断连、无效路径、坏包、视觉重启、主控复位和STOP；记录触发时间、输出停止时间、轮子停稳时间/距离，验证恢复数据后需新START。

主控：基础跑圈稳定后，实现离开起点后才允许完成一圈判定、终点去重、语音命令映射、动作结果反馈。视觉负责识别与语音应答。STOP持续保持高优先级，STATUS回包与应答需新增实现。

验收：整车真实停车满足共同确认的要求；起步不会被终点标记误停；识别到语音命令与动作实际执行结果能够区分。比赛具体要求沿用正式文件及后续通知，不以本规划替代。

## 建议工作节奏

以下按有效工作日安排，是顺序建议而非已承诺的日历期限；每阶段未通过验收时，优先修复再继续。

| 工作日 | 重点 | 当天应展示的结果 |
| --- | --- | --- |
| 第1天 | 实物核对、下载、板上运行 | 能烧录，复位后状态正确 |
| 第2天 | 串口模拟包、协议确认 | 启动/停止/超时在板上生效 |
| 第3天 | 电机开环、编码器起步 | 悬空受控转停，能看到计数 |
| 第4天 | 编码器标定、单轮闭环 | 轮速单位明确，单轮跟随目标 |
| 第5—6天 | 双轮闭环、地面直行、停车 | 稳定低速直行、实际可停车 |
| 第7天起 | 视觉循迹与整圈回归 | 逐步达到连续3次低速整圈 |

当天最小完成项：核对板卡与下载器 → 不接电机供电 → 打开HardwareBench → 编译下载 → 观察计数、IDLE和零请求 → 复位复测 → 保存记录。

主控每次收工保存代码版本、引脚/参数变化、测试结果和下一项阻塞。接线与供电资料放 `hardware_preparation/`；工程与技术说明放 `control/`；跨模块试跑日志及录像索引放 `testing/`。修改通信或状态机后，重新执行现有电脑测试和相关Keil编译；纯记录更新不需要重新测试固件。

依据：`control/README.md`、`control/docs/keil_quickstart.md`、`control/docs/pin_plan.md`、`control/docs/protocol_v1_draft.md`、`control/docs/state_machine.md`、`control/docs/validation.md`及当前 `board.c`、`board.h`、`main.c`。
