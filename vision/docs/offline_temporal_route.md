# T2多帧、二维路线与五节点地图候选

负责角色：视觉。任务：[V-06](../../project_planning/tasks/V-06.md)。研发日期：2026-11-09。最终源码与统计以[本轮报告](../../testing/2026-11-09_vision_temporal_route_t2/review.md)及其中链接的冻结输出为准。R1/C1/C2/P1、原图、旧参数和旧视频保持原状。本模块未操作板卡或改变控制策略。

## 当前输入与人工确认

输入320×240 uint8灰度图、会话键、原始采集软件毫秒、当前R1阈值、C2当前接受的成对锚点，以及独立F1当前确认的终点事件。算法接口不接收帧号、总帧数、未来图像或人工逐帧转弯表。

主控确认两圈录像使用图1五节点布局，车头朝图中左侧、始终顺时针；初始整车投影在虚线后即右侧，最终整车投影在虚线前即左侧。录像用于两圈开发评估，比赛目标配置 `lap_limit=1`。相机无法验证车尾位置，整车越线事实仍标为主控确认，不能由F1事件推导。

## 算法和边界

[offline_temporal_route.py](../src/offline_temporal_route.py)独立实现以下步骤：

1. 使用中央20／40／60cm三条量距参照得到纵向分式投影，再加平地、固定相机和直道50cm净宽假设建立候选二维平面。横向gain=48是近似参数；初始直道由其换算的宽度约48.9～52.2cm。中央20～60cm以外仍未完成真实二维标定，不能称完整逆透视已验收。
2. 对前后两帧地面ROI做金字塔LK、前后向误差检查和RANSAC，再强制拟合刚体运动。检查内点数量／比例、空间分布、缩放、残差及跳变；失败即撤销像素融合，不补恒定速度。累计光流转角仅作诊断，真实两圈只累计约122°，不能用于单独计弯或声称里程计可用。
3. 最多6帧、真实时间1200ms的黑带证据，按相邻运动投到当前候选地面平面。当前证据权重较高；拒绝部分附着上缘的宽厚背景组件，但仍不具备家具／文字语义识别能力。
4. 同时拟合直道与当前地图节点的二维折角。道路边界是沿路径方向偏置的折线，能表达向图像侧方转出的道路，避免把单条黑带两面当50cm道路。当前C2中点约束模型；单边还需与历史模型关联，两侧黑像素支持还检查不同组件。所有模板边界始终是推断，不能升级为实测。
5. 用接近、转弯进度、近端角点经过及新路段观测推进五节点顺序。顺序为左下直角90°、左肩38.5°、顶部转向103°、右肩38.5°、右下直角90°。这里103°是约77°内角的补角，肩部角度由图形作几何先验，未经现场量角。不按“看见一个角”立即计弯，也不按帧号／固定时间计弯。五节点后进入finish_straight，等待独立F1终点观察才解开下一圈的开发跟踪，避免把末弯重复计作下一圈。比赛lap_limit仍为1；独立F1终点事件可重新定位到起终点路段，漏失节点重新定位须显式记录。弱拓扑推进不清空仍有效的强路径历史，也不提升路径可信度。
6. 折角中心路线用候选20cm半径切圆弧连接，形成推荐模型线。半径仅是离线演示参数；未验证转弯半径、车辆包络、速度或侧滑。完整局部路线另存在 `recommended_path_ground_full`，包括相机近端盲区；画面线只画可投影的前方范围。路线在画外时看右侧俯视图，不夹造图像坐标。

这是几何模板与时序状态候选，没有实现完整SLAM、贝叶斯全地图定位或神经网络训练。保留直道／弯道两个局部解释，地图节点仍有单一阶段假设，漏计与错误重定位仍可能发生。文献比较见[研究记录](../../testing/2026-11-08_vision_temporal_map_research/research.md)，不称“全网最好”或保证最快完赛。

## 状态、时间和输出

| 字段／状态 | 含义与后续控制边界 |
| --- | --- |
| `current_supported_model` | 几何模型获得当前黑带支持并通过相应关联检查；不是双边实测、定位准确或安全路径保证 |
| `history_prediction` | 当前支持不足，只显示运动变换后的有限历史模型；超过1200ms撤销 |
| `current_pair_fallback` | 当前双边已出现但模板不相容，撤销旧模型，仅输出当前范围的双边中点参考；不是完整弯道路径 |
| `map_prior_only` | 仅能画未验证名义路线；建议停车／重新定位，不得执行该线 |
| `map.node` | 当前目标节点假设，不是厘米级车辆位置；未初始化为unknown |
| `finish_observations` | 独立F1确认的终点观察次数；不等于车尾越线或自动停稳 |
| `competition_finish_seen` | 第一次终点观察后置位，用于开发诊断；不发送STOP、不验证整车越线 |
| `protocol_valid/control_ready` | 始终False；候选不改固定y120偏差，不映射heading/bend，不改唯一20字节协议 |

捕获间隔>700ms、时钟回退／缺失、会话切换会清空相应历史；中途时钟复位还撤销起点地图初始化，不能把中途新帧误当第一弯。重新捕获允许恢复当前空间模型，地图定位仍需独立有效锚点。建议减速或停车只是软件诊断，未改STM32策略／增益。

## 可复现运行

所有输出目录必须尚不存在，拒绝覆盖。新环境先按[PC环境](../PC_ENVIRONMENT.md)安装 `requirements-review.txt`，只在电脑运行：

```powershell
vision/.venv/Scripts/python.exe vision/tools/replay_temporal_route.py --output vision/build/temporal_route_new
vision/.venv/Scripts/python.exe vision/tools/validate_temporal_route.py --output vision/build/temporal_route_checks_new --mask
vision/.venv/Scripts/python.exe vision/tools/make_temporal_route_preview.py --input vision/build/temporal_route_new/frames.jsonl --output vision/build/temporal_route_video_new
```

回放共1394张正式素材，旧325无可信时间时不融合历史／不初始化地图；中断20张另审计，不把第21张超会话提交计数的JPEG混入完整组。回放同时保存P1/C2原字段；T2字段单列。源码在回放前快照并检查结束哈希相同，避免开发中修改源码造成归因不清。

## 板上、通信与得分

当前依赖电脑NumPy/OpenCV的LK、RANSAC/SVD、连通域、距离场、透视变换和向量化模板搜索；CanMV Python不是电脑OpenCV环境。数组工作区和搜索开销须重新缩减／原生化，不能直接复制到K230的main.py；电脑算法时间不等于板上端到端延迟。可先移植的范围是节点状态、真实时间清空规则和诊断字段，核心二维运动／搜索仍需板上适配与性能验证。

沿用[V-08板上准备](../../project_planning/tasks/V-08.md)和[无动力通信检查表](board_preparation.md)。本候选未加入UART有效路径，也未拓展20字节协议；现有协议不能表达多帧推断来源、地图节点、局部路线及失效原因。需要由00协调双方确认接口之后再接控制，不占用保留位。本次不打开采集、覆盖main.py、连接实体UART或运行电机。

多帧恢复与路线估计目标为支撑基本功能60分、减少触边／出界／无法完赛风险；可复现实验与失败分析支撑报告20分；F1的后续终点处理可支撑额外功能40分中的相关内容。没有实测圈时／得分收益。连续黑条尚未证明可泛化到官方5cm离散色块。下一步实物验证仍需最终安装下的二维地面几何与板上无动力性能检查，本轮无需补拍或上电。
