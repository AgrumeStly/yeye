# V-02 电脑端离线边界回放

日期：2026-11-07，更新至R1。维护与现场责任：主控；本页仅说明电脑端实现。依据：[任务](../../project_planning/tasks/V-02.md)、[比赛项目要求和评分表](../../competition/比赛文档.md)、[赛道图](../../competition/assets/track_figure_1.jpg)。R1限定修正及交付已通过[原对话独立审核](../../testing/2026-11-07_vision_offline/r1/audit.md)，首版输出和证据保留；下一步为V-03静态视场核验，尚未验证板上或整车。

在项目根目录 PowerShell 运行，使用现有环境，无需安装依赖：

```powershell
vision/.venv/Scripts/python.exe vision/tools/replay_offline.py --input vision/data/captures/d01_straight_run01 --output vision/build/offline_v02_r1 --headless
vision/.venv/Scripts/python.exe vision/tools/check_offline_replay.py
vision/.venv/Scripts/python.exe vision/tools/compare_offline.py
```

第一条生成325张叠加、JSONL、CSV、统计、实际参数和 `preview.mp4`。第二条核对来源、失线清空、近水平条带／墙体／场外错配几何回归及采集哈希。第三条生成325行首版／R1比较、有效性转换清单、扫描行覆盖统计、37组审核页及三列 `comparison.mp4`。审核证据见 [R1 review.md](../../testing/2026-11-07_vision_offline/r1/review.md)。完整输出在 `vision/build/offline_v02_r1/`，build被Git忽略，仅在本机，不自动跨设备同步。首版 `vision/build/offline_v02/`及独立复跑 `vision/build/offline_v02_audit/`保持原样；首版源码快照保存在 `testing/2026-11-07_vision_offline/r1/baseline_source/`。

输入严格匹配 `data_数字.jpg` 并按数字排序，禁止用 `dbg` 叠加图或损坏的 `collect_log.csv` 作算法输入。现有采样是手推，不能推算真实采集帧率、圈界或自动完赛。`--fps 10` 为默认人为预览速度，325帧视频约32.5秒。`--headless` 明示无窗口，省略时仍无窗口。可用 `--config 参数.json` 覆盖集中参数；默认参数定义在 [offline_boundary.py](../src/offline_boundary.py)，每次运行完整保存为 `parameters.json`。

算法只支持当前320×240 uint8灰度输入。ROI为y=65..215，每5行取3行灰度中值剖面，计算ROI大津阈值并用背景灰度与上限约束。R1另用71像素水平闭运算估计局部亮背景，在原灰度上补充落差≥20的深色候选，应对反光使黑条高于全局阈值。闭运算不修改原图，不直接填补边界点。横向黑段3..55像素、内侧对比≥12、3像素边缘保护继续保留；黑条外侧可出画，图像边框不能充当内边缘。两候选间须有白色内部、合理间距，再通过同帧逐行位置连续性关联。对弯道保留局部折线，不用全局直线覆盖整幅道路。间距限制只拒绝退化配对，不是补线用的路宽标定。

R1另沿x每5像素竖向扫描，限制深色条y厚度3..32像素、上下对比≥12、不能触ROI上下沿；沿x关联并要求跨度≥60像素，保留61／111近水平条带。`visible_ribbons`保存同一条黑带的上／下轮廓，侧别`unassigned`、`road_side_ambiguous=true`；青色点只是可见候选，**同一黑带两轮廓不等于道路左右边**，不参与有效中线判定。上方大墙回归被拒，但不保证所有场外物均排除。

只有双边至少6个支持行、跨度至少25像素、质量足够且包含参考行时才给出可用中线。R1增加候选对宽度随y向近处增大的最小斜率0.2像素／像素检查，拒绝81／191中同向场外条纹；251仍依赖原支持数／质量门槛拒绝。该保守检查会拒绝部分偏航／转角，不是标定模型。中心逐行取左右内边缘中点；质量为双边支持数量（12个饱和）乘行密度，是启发式评分，不是正确概率。偏差固定在y=120：`dx=center_x-159.5`，像素为单位、右正；归一化为 `round(dx/159.5*1000)` 并限幅到−1000..1000。归一值仅供离线审核，不发送数据，也不修改协议。未标定，无厘米、真实航向角或物理曲率输出。

没有可靠双边时保留所关联可见点，缺失侧为 `missing`，中线为空、偏差为null、`valid=false`。单边不补另一侧；侧别由画面位置暂定，并以 `single_boundary_only_side_ambiguous` 明示有歧义。R1以`unpaired_boundary`另存完整单边候选，避免弱配对遮蔽主边，无效叠加中用淡蓝点显示。没有跨帧状态，每帧独立重建；回归片段重新创建检测器。无效帧绝不回用旧路径。点状态只有 `visible`，不产生 `inferred`；它表示观测到的候选，并不保证确实为赛道。

`frames.jsonl` 每行含原文件、编号、SHA-256、读取状态、左右点及状态、候选对、可用中线、质量、有效性、原因、参考行和偏差、算法耗时、叠加相对路径。R1增加`algorithm_revision`、`visible_ribbons`、`unpaired_boundary`、`pair_width_growth`、`reference_diagnostics`。参考行诊断记录原始全局黑段、局部候选、边缘保护／裁切现象及支持范围，不将检测不到一侧直接断言为出画。`frames.csv`是摘要，完整点集查JSONL。叠加左绿、右橙、中线紫、黄色参考行，原图下附状态字幕。失败原因可并存，原因计数不能直接相加当无效帧数。

电脑算法计时仅包围 `detect()`，不含读图、画图、保存或编码，不代表K230D性能或端到端延迟。输出MP4采用本机 `mp4v`，结束后逐帧重新解码核对数量；失败时写 `VIDEO_ERROR.txt` 并返回非零，仍保留叠加序列。读取失败也输出占位叠加及明确原因，返回非零。

R1为162有效／163无效，首版160／165，仅124、281恢复有效；六个指定成功例保持有效。主要改善是可见候选覆盖，不能把197帧出现补充条带称为197帧识别正确。41／301的参考行右边仅剩极窄截断、171缺少右侧、211远段阈值碎裂改善但参考行无右侧支持，继续无效；首版将这些统称明显漏检的解释已由独立审核纠正。201–325已公开，本轮只能称旧数据回归，不是新独立盲测。

当前证据主要是这批连续深色条样本，尚未验证官方5cm黑色色块间隙、完整锐角进出或起终点虚线。边界角色歧义、场外错误配对、反光及参考行视场不足仍存在；局部中点不是可直接下发的整车可行轨迹，转角还需标定与车体包络验证。本任务支撑基本功能60分的可靠完赛／降低触边风险及报告20分论证，没有官方识别率阈值、实测得分收益或上车许可。
