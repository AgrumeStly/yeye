## 当前这一趟怎样推

这一趟先采77°弯，不要求整圈。当前限时45秒是本次采样安排，不是比赛规定或自动终点识别。

1. 主控保持相机现有安装、320×240灰度配置，**电机动力保持断开**。先将车放在通往顶部77°弯的左侧斜直道中央，车头沿入口直道朝向顶角。起点建议在内侧尖角前约60cm；距离沿入口方向，参照“经过内侧尖角、垂直于入口方向的横线”量到车头最前沿，不沿外侧黑边量。
2. 主控用车载稳压供电给视觉板上电。系统启动／相机预热和写卡预检完成后，程序继续准备15秒；因此不是从电源开关拨动起精确15秒。主控听开始提示，不按秒数猜开始。
3. **一声约0.6秒长音结束后开始推车**。保持车体在车道内，沿平滑右转路线缓慢推进；车身逐渐转向，相机随车身转，不单独扭镜头，不在尖角处原地突然转车，不遮住镜头。
4. 从入口完整经过弯中，直到车头对准右侧出口斜直道，再沿出口前进约40cm；这是这趟的推行终点。距离是操作建议，短段空间不足时以整车不触边、完整看到出口恢复为先，记录实际结束位置。
5. 到达终点先停在原地，保持供电，等**两声长音**全部结束，再等约2秒后关电。采集窗口为开始长音结束后45秒，提前推完后会继续拍静止画面，不需要为了等声音继续推远。如果两声结束音在推到终点前就响，本趟没有完整覆盖，留原件并记录，不为了赶时间加速冲过弯。
6. 如果响的是**5声短音一组、共两组**，表示采集失败；停止推车，保留卡内部分文件和错误元数据，连接电脑检查。没有任何开始提示时也不应盲推。

45秒内以缓慢、平滑、完整进出弯为目标，通常先预留约30秒完成推行并在终点静止；不要求按固定速度走出所谓“标准路径”。这些手推图只验证视觉连续性，不是车辆自动可行路径、轮胎转向能力、触边次数或完赛证据。比赛按顺时针行驶，正式测试禁止人工干预；本流程是赛前人工采样。

## 提示与文件

| 现象 | 意义 | 主控动作 |
| --- | --- | --- |
| 上电后暂时无声 | 系统启动、预热／写卡检查、15秒准备 | 保持起点不动 |
| 1长音 | 即将进入45秒采集窗 | 长音结束后开始推 |
| 采集中无声 | 正在连续保存 | 手推通过弯道 |
| 2长音 | 停采、相机清理和文件同步成功后发出 | 等两声结束再等约2秒关电 |
| 5短音×2组 | 卡／相机／写入／清理等失败 | 停止推行，保留文件 |

保存的是连续未叠加灰度JPEG照片及日志，不是板上MP4；电脑可以据此生成回放视频，便于逐帧检查识弯。JPEG是有损编码，不称传感器RAW。目标保存间隔100ms，实际受拍摄、编码、写卡和校验影响；短时测试实测约8.5张／秒，不保证45秒实际帧数。

每次启动自动新建`/sdcard/captures/push_corner_77_0001/`、`0002/`等，旧会话不覆盖。里面有`data_0001.jpg`等、`frames.jsonl`和`session.json`。这是一趟一次性程序，采完退出，不自动再采；再次上电会新建另一组。不要刚采完就带电拔卡或中途断电。

主控关电后可取卡复制完整新会话，或重新连CanMV后先停止可能启动的新一趟，再通过文件面板下载。电脑保存到`vision/data/captures/final_mount_20261108/<实际会话名>/`，不要覆盖旧组。重新上电下载可能额外新建一组，须根据`scene`、计数、状态和会话编号区分，不能把不完整下载会话混入正式手推组。

```powershell
vision/.venv/Scripts/python.exe vision/tools/verify_push_capture.py vision/data/captures/final_mount_20261108/push_corner_77_0001
vision/.venv/Scripts/python.exe vision/tools/replay_curve_offline.py --input vision/data/captures/final_mount_20261108/push_corner_77_0001 --output vision/build/push_corner_77_0001_c1
```

目录名替换为实际新会话。第一条验证schema2、完整状态、帧数、哈希、解码和软件时间。第二条使用C1回放，输出目录须未存在；视频默认10fps只是人工播放速度，真实间隔另查日志。原静态`verify_capture.py`只接受schema1，不用于这个定时采集版本。

主控提出车载电池供电，但本工作区尚无本轮视觉板电池接法实测记录，异步问题仍待反馈。电池应经适配稳压线路给视觉板供电，**2S电池原电压不能直接接视觉板5V／Type-C电源端**，不能将驱动板可能携带原电压的Vout误当5V稳压输出。电机与视觉板供电须能分别处理；本程序不负责阻止另一个STM32程序驱动电机，采样时电机动力要实际断开。参照[既有供电边界](../../hardware_preparation/wiring.md)和厂家[电源网络说明](https://wiki.lckfb.com/zh-hans/lushan-pi-k230/faq.html)，不以软件通过代替电气核验。

## 接口依据与验证范围
