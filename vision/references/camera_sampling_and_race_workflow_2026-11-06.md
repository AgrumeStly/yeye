# 视觉采样与比赛闭环执行建议

日期：2026-11-06。依据：主控本轮询问视觉任务、赛道取样、双边界视场、偏离姿态、弯道通过及算法选择；已读比赛转写，并实际查看原PDF第2、3、4页渲染图、图1及评分表。本文是供视觉、主控、硬件和00评审使用的工程建议，不宣布新接口、实物验收或官方评分细则。

现有依据：[比赛原文](../../competition/比赛文档.pdf)、[可检索规则](../../competition/比赛文档.md)、[赛道图](../../competition/assets/track_figure_1.jpg)、[V-01](../../project_planning/tasks/V-01.md)、[识别方向](recognition_direction_2026-11-01.md)、[相机安装](../../hardware_preparation/camera_mount_guide.md)、[唯一结果包协议](../../control/docs/protocol_v1_draft.md)。全局摘要早于部分控制任务，控制进度另看[C-02F](../../project_planning/tasks/C-02F.md)、[C-02G](../../project_planning/tasks/C-02G.md)，不把悬空同速或独立直线程序当作循迹已完成。

## 1. 方向与得分

建议沿用Lite-K230D-CanMV与项目已有摄像头体系，首版用传统几何视觉：灰度分割、左右边界关联、局部中线与方向、锐角提示、可信度及终点候选。无需先训练大模型。当前新到摄像头的实际镜头／型号还需随实物归档；不能仅凭GC2093芯片名确定视场。

| 工作 | 官方条款／评分项 | 预期作用 | 应留验证证据 |
| --- | --- | --- | --- |
| 固定相机、可靠边界、姿态与光照采样 | 第三部分项目要求；基本功能60分 | 支撑顺时针、5分钟内完赛，降低触边扣分和完全出界失败风险 | 原图、边界叠加、各类误检／失线、整圈成功率和触边次数 |
| 锐角提前减速、差速转弯、直道提速 | 基本功能60分按用时折算 | 在保持完赛率与边界余量时降低圈时 | 可用预瞄距离、延迟、减速距离、速度与转向日志、全部试跑圈时 |
| 终点与语音 | 额外功能40分 | 完成语音启动／接管／应答／不少于2条自选指令、冲线自动停车 | 实车独立演示，冲线与停稳位置，语音接管3秒内停稳记录 |
| 数据、版本、失败与改进对照 | 报告20分 | 为方案、理论、电路程序和规范提供可核查材料 | 参数版本、流程、原始样本、同条件前后对照 |

官方未公布具体用时折分公式、每次触边扣分及40分的分项分值，不能保证本建议增加多少分。下文距离、角度、次数、频率和延迟均是队内起点，不是官方门槛。

## 2. 视觉现在交什么

1. 复用已有采图成果，归档板型、摄像头及镜头、固件版本、可运行脚本、采集尺寸／格式／裁剪／镜像、启动方法和安装照片。电脑已安装OpenCV不表示CanMV板上可以直接使用cv2。
2. 按V-01先交现有20字节协议的固定测试包发送器，再接真实视觉结果；固定包与真实结果分开留证。视觉和主控确认符号／量纲／序号／CRC，02组织真实互通。
3. 采集本页规定的实车视角样本，输出左右边界、中线、近处偏差、前方走向、弯道强度、质量分和有效标记；生成逐帧叠加回放。
4. 与主控共同完成低速循迹、锐角减速／差速、丢线与断流停止，再分档提速。视觉负责识别，主控负责STM32运动控制，硬件负责稳定结构与供电，02组织实车验证。
5. 视觉并行安排语音和终点候选；主控接动作与一圈状态。当前协议STATUS没有回包／动作完成反馈，终点候选也不会自动判定完成一圈；接口扩展交00协调，不能把播报“已停车”当作机械停稳。

## 3. 相机怎么装与怎么用

先依[安装建议](../../hardware_preparation/camera_mount_guide.md)试装：镜头中心离地约18cm、光轴相对水平向下约40°、车身居中且朝前，支架刚性固定。18cm／40°仅是起点，应依据实际镜头和画面调整。整车连同支架、排线必须长≤30cm、宽≤20cm、高≤25cm、含电池≤5kg。

调试时使用VS Code中项目已有CanMV扩展预览，或已确认可运行的采图工具；不必换掉现有入口。先核对静态画面方向和黑块清晰度，再录制手推动态画面。相机一旦改高度、角度、焦点、镜头或裁剪，原ROI和地面映射均须重新核对。

算法画面先比较192×120与320×240灰度图，按远处5cm黑块是否可辨、端到端延迟及失线表现决定。厂家文档说明输出宽度按16像素对齐，必须读取实际尺寸。原始灰度或彩色帧用于回放，二值图和叠加图作为派生产物；不要只留二值图。

曝光／白平衡接口以实际固件为准；厂家当前教程仍说明相关API限制，不能照搬OpenMV的锁曝光调用。存在运动模糊时分别检查焦点、支架振动、采集配置及实际可用的曝光控制。

**两侧边界尽量在有效观察区域内同时可见，不要求每一行、整段边界或画面底部均双边可见。** 近处用于看横向位置，中处用于关联两边，远处用于提前看弯道。窄镜头可能底部只有白路面，中上部才同时看到两边；应选择可用ROI，不直接判定失败。正常居中直道若整个有效区域都无法得到可靠双边信息，应先调整视场。

弯中或偏斜时单侧出画应纳入算法测试。可依据标定的透视／局部几何有限推断另一侧并降低质量，不能用全图固定像素宽度；转角处不能把直道逐行宽度直接套用。两边不可信就报无效。当前协议遇新无效／低质量帧立即FAULT，不能预期主控自动容忍数帧后继续行驶。

## 4. 到赛道哪些地方拍

按官方图顺时针：底部起终点向左出发 → 左下角 → 左侧短直道 → 左肩角 → 左斜直道 → 顶部锐角 → 右斜直道 → 右肩角 → 右侧短直道 → 右下角 → 底部直道 → 终点。图示路线的五处转弯均为右转，但每处仍需采车头向左／向右偏斜的纠偏画面。

顶部标注约77°是图示夹角，不应直接写成电机“右转77°”。按入弯、出弯切向推导的航向改变约为180°−77°=103°；这是图形几何推导，实车仍靠实时路径闭环，不能定时盲转。

| 地点 | 核心样本 | 主要检查 |
| --- | --- | --- |
| 起终点 | 起步静止、离开起点、回到终点前、越线和越线后 | 横向虚线与左右黑块分开；起步不误停车；提前看到终点不等于冲线 |
| 各条直道 | 居中、横向偏左／偏右、航向偏左／偏右 | 偏差符号正确、道路宽度合理、远处黑块能辨认；长斜直道也要拍 |
| 左下／右下两处约直角弯 | 远处首次看见弯、接近、开始转、弯中、出弯 | 何时提前减速、前后边界如何关联、转弯时车体是否触边 |
| 左肩／右肩两处较缓转角 | 相同五阶段 | 避免漏转或反复左右摆动；观察短直道衔接 |
| 顶部约77°锐角 | 加密采进入、方向变化最大处、单侧出画及重新看到出口的连续帧 | 进出弯分段关系、可行转弯空间、可靠视距；不能一条直线拟合整个转角 |
| 光照／干扰 | 阴影、反光、拼接纹理、外围人员走动及明暗变化 | 不把阴影、场外黑物或人员当作车道边界 |
| 失效状态 | 单边缺失、两边缺失、模糊／遮挡、采图断流 | 有效标志、质量、FAULT与实际停止，避免旧数据伪装新帧 |

不为采集加入比赛依赖的额外标记或场外定位装置。标定板只用于赛前单独标定，结束后移除；正式自动运行不得依赖电脑或场外设备。赛前手推／人工摆姿仅用于采样，不是正式测试中允许人工干预。

## 5. 弯道怎样摆车、怎样拍

始终使用固定在实车上的摄像头。手机侧拍／俯拍可作车体触边证据，不能代替车载输入。不要让相机单独朝向出弯方向，要转动车身并保持相机相对车身的安装不变。

**静态采样：先断开电机动力，保留视觉板安全供电。** 沿车道中的可行平滑路径，依次摆出接近、进弯、弯中、出弯姿态。每次拍原图并记录路段与姿态；不要在赛道几何尖角处原地突变方向作为唯一正常样本。

具体起点建议：

1. 在弯道前约60、40、20cm各拍一组；再拍开始转向、弯中和出弯后约20、40cm。距离仅辅助复现，短段放不下或视场不足时按实际调整。进入弯道的距离沿入口方向记录，不能把量尺读数与真实预瞄距离混同。
2. 先拍中心位置、车头沿当地路径方向的正常姿态，再挑接近、弯中、出弯各一处补异常姿态。
3. 横向平移分别试偏左／偏右约5cm；余量足够再拍约10cm。保持车头朝向不变，用于区分位置误差。
4. 同一位置分别试车头偏左／偏右约5°、10°，用于区分方向误差。最后只挑少数“偏位置＋偏方向”组合，覆盖真实纠偏状态，不必一开始穷举全部组合。
5. 每次先检查车身四角、轮胎、支架、线束的完整投影未触边。靠边的失败画面可静态留样并注明，不能将其混为正常可行路径。

**需要拍拐弯时微偏离的视角。** 应分别拍偏弯内／偏弯外、转早／转晚、转向不足／转向过多。只拍完美居中的样本，无法验证真实纠偏、单边缺失和恢复过程。偏移与航向须分开记录，避免同一种画面偏差被错误理解。

静态覆盖后，手推实车沿同一平滑路径拍连续短片：从足够远的入口开始，经过弯中，一直到出弯重新稳定。每个弯先录约3遍，包含正常姿态和轻微偏离；锐角优先加录。每段完整进出弯通常几秒至十几秒，按推行速度决定，不为凑时长截断过程。不能只留转弯最中央一张图片。

手推只验证几何连续性和部分模糊情况；电机振动、实跑曝光、负载及速度影响须在后续低速通电试跑补录。低速试跑需先完成通信与停车检查，由02组织，不能据本建议直接跳到高速。

第一轮最低覆盖：一段完整顺时针手推回放；五处弯各一段完整进出弯；各类直道姿态；起步／回到终点；单侧及双侧失效。照片数量服从场景覆盖，不以“拍够1000张”作为验收。

## 6. 怎样保存、标注和验证数据

使用English目录，例如`vision/data/2026-11-06/session_01/`，按`straight`、`corner_left_bottom`、`corner_left_shoulder`、`corner_apex`、`corner_right_shoulder`、`corner_right_bottom`、`finish`、`failure`分场景。名称中的left／right指地图位置，不指转向。

每段保存原始帧／短片、时间戳与帧号，关联固件与代码版本、镜头、安装高度／俯角、采集尺寸与裁剪、光照、姿态标签、是否手推／通电、速度来源及运行日志。偏移无法测准时写定性标签，不编造厘米数；叠加图与原图分开。

人工标注选定关键帧的左右内侧边缘、可见／推断／不可见状态、进弯／弯中／出弯、终点有无。算法画出边界和路径，逐帧检查误关联、漏检和抖动。连续短片按采集批次分成调参集和独立验证集，不将相邻帧随机拆散造成虚假的泛化结果。条件允许再留不同光照的一整圈作最终检查。

这些数据首要用途是调阈值、验证几何、回放错误和测试回归，不是训练大模型。只有传统方案在明确场景持续失败，并证明小模型能在本板实时运行且独立数据上改善时，才比较轻量分割等方案；引入模型不能挤掉通信、停车、语音和整车验收。

## 7. 首版算法怎样做

1. 灰度图取道路有效区域，比较固定阈值和ROI内大津阈值；若局部阴影持续影响，再评估局部阈值。CanMV内置运算承担图像处理，Python组织候选和状态，避免全图逐像素解释执行。
2. 近、中、远放约6–10条横向窄带，找多个黑块候选，按位置连续性、局部方向、合理宽度和前帧关系关联左右边界，取面向白路面的内侧轮廓。
3. 实拍核实黑块间隙。不能假设黑像素全部连接；八邻域可能绕单个色块，白区填充可能穿间隙连到场外。跨块关联需与实际图像匹配。
4. 双边可信时计算局部中线及近处误差；远处估计路线走向和弯道强度。弯道用分段几何，必要时增加局部轮廓／折线拟合；一条横向扫描带可能有多个交点，不能永远取最左／最右黑点。
5. 锐角分开识别入弯与出弯边界，生成白色可行区域内、满足车体包络的平滑路线。起步先用保守中间路径；速度成熟后才评估扩大转弯半径的路线，不能直接把两段中线连接成穿过内角的切线。
6. 质量分来自有效覆盖、拟合残差、宽度与时序一致性；终点横向虚线另判，不当作侧边。输出必须能追溯到真实帧；丢线发新序号无效帧，不能新序号反复发送旧识别结果。
7. 平面标定／逆透视可在基线可用后补充，优先变换少量边界点；未标定的bend仅称弯道强度，不能标成物理曲率。

现有`vision/reference_code/`为待适配C例程，移植审查已指出越界、旧路径残留等缺陷，不直接作为板上工程。十字／环岛不是本届必需任务，不优先做无关元素。

## 8. 小车怎样过弯、怎样提速

视觉持续给出路径和可信程度；主控用差速改变航向，并由两轮速度闭环执行。右转时通常左外轮目标速度高于右内轮；双轮同速只是直行基础。地面仍可能因轮胎、负载打滑跑偏，编码器同速不能代替视觉方向修正。主控必须核对当前左右轮映射与正方向。

弯道过程：提前看到方向变化 → 在进弯前完成所需减速 → 低速沿可行路径差速转向 → 连续确认出弯路径稳定 → 平滑恢复直道速度。不得只靠固定时长转弯或等近处偏差很大才减速。低速原地旋转只有在全车扫过区域已验证不触边时才可评估，不作默认过弯策略。

50cm净宽、20cm车宽时，居中正向直行理论单侧余量仅15cm；若矩形包络长30cm、宽20cm，在直道相对道路偏航45°，横向投影约`20cos45°+30sin45°=35.4cm`，居中单侧仅约7.3cm。实际弯道两边方向变化，须检查整车四角与附属物扫过区域，不能用这一简单直道估算替代弯道验收。

提速前测可用预瞄距离、最坏可接受画面年龄、真实减速度和弯速。初步核查可用：

`可靠发现弯道的距离 ≥ v×总延迟 + (v²−v_bend²)/(2×a) + 安全余量`

这是恒定减速度近似，距离必须从一致的车体参考点沿路径计量，并计入相机与车头偏置；a须由真实负载、地面、电量下减速测得。实车滑行、抓地和转向能力另测。例如1m/s、80ms延迟已前进8cm；2m/s则为16cm，尚未包含减速。若画面只支持短预瞄，不能单靠拉高电机转速获得可靠快圈。

路径有效更新可先以50Hz为优化目标；给出真实新图像的更新频率，不能用重发旧结果凑数。延迟记录中位、95分位和最大值；95分位≤50ms可作队内优化参考，最终上限由速度与视距决定。`processing_ms`不含完整采集、排队、发送与控制响应，不能代替总延迟。

先低速连续3圈零触边作为队内初验；随后每次只改一组参数，按约5%–10%的小档试提速度或分别调直道／弯道速度。关键档至少记录10次全部尝试的完赛率、触边次数、圈时中位数／最差值和失败前视频；这些次数不保证可靠性，但能避免只挑最快成功一次。失败回退并分析后再试。

## 9. 终点、语音与最终交付

终点状态建议：起步锁定 → 确认离开起点 → 行驶过程／里程核对 → 重见终点虚线 → 结合相机与车体几何确认冲线 → 自动减速停稳。里程和转角序列作辅助，不单靠计时／轮程判定终点。原文“垂直投影越过终点线”的具体裁判判定应向主办方核实，不能自行宣布仅车头或全车通过为官方解释；工程验证需记录整个越线过程。

语音须由车载独立完成启动、接管、清晰应答及不少于2条自选指令。接管验收从语音指令到机械停稳计时，必须≤3秒。自选指令可考虑待机状态查询、电量播报等，但必须已有真实数据或明确待机状态，不编造测量结果；当前协议若缺支持，应由00协调。语音播放与识别需测试自激误触发、运行噪声及是否阻塞视觉／STOP处理；应答内容与实际接收／动作状态对应。

最终应交可离线启动程序、采样与叠加回放、参数与安装记录、真实UART日志、延迟统计、各速度档的全部整车记录、语音／自动停车证据和报告素材。当前完成的是建议与规则核对，尚无本轮新采样、板上识别、串口或整圈实测结果。
