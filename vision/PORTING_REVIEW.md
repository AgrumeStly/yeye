# Vision porting review

核验日期：2026-10-10。目标硬件：立创庐山派 Lite-K230D-CanMV + GC2093；天空星 STM32F407VET6 负责运动控制。

## 结论

算法可以复用，当前文件不能直接作为 K230D 的 CanMV 脚本运行。它是面向 MT9V03x 摄像头、IPS154 屏幕及相应 MCU 工程的 C 语言示例，还缺少完整采集驱动、控制输出和通信链路。原作者辅助文档也要求替换采集、显示接口。

建议保留“灰度分割 → 左右边界 → 中线/拟合”的思路，用 CanMV Python 调用固件内置图像处理函数实现第一版。Python 负责流程、参数和通信，尽量让整幅图的扫描、二值化及区域检测在底层函数中完成。不要直接把 C 的全部逐像素循环翻译成 Python。

可以在 K230 的原生开发环境中移植 C 算法或加入原生模块，但这涉及工具链和固件构建，对目前只有一位 Python 视觉队员的团队，首版不优先选择这条路线。

## 已检查的输入

目录整理说明：以下 C 文件现位于 `reference_code/`，辅助 PDF 位于 `references/`，图像表格位于 `data/`；下文代码行号仍对应原始文件，文件内容未修改。

- `image.h`：固定 188×120；自定义整数类型、两幅图像缓冲。
- `image.c`：图像复制、大津阈值、二值化、原地形态学过滤、八邻域追边、边界提取和显示。
- `十字补线和最小二乘法.c`：线性拟合、十字检测及补线。
- `智能车图像处理辅助文档V2.0.pdf`：15 页；原理、平台替换与示例效果。
- `图像.xlsx`：一张 60×94 的二值图，取值为 0/255；适合作为离线示例，不能代替真实赛道数据。
- 工作区 `competition/比赛文档.pdf`：白色车道、连续排列黑色色块边界、净宽 50cm、至少一处锐角转弯。该规则没有要求十字或环岛任务。

## 原代码的问题，按修改优先级排列

| 优先级 | 位置 | 问题与影响 | 建议 |
|---|---|---|---|
| P0 | `image.c:352–355` | 第一轮 `r_data_statics=0`，重复点判断会读取 `points_r[-1]`；左侧统计为 1 时也可能读负下标。这是未定义行为。 | 只有收集到足够点数后才能比较最近三个点；左右统计独立校验。 |
| P0 | `image.c:299–328`、`394–395` | 邻居坐标使用 `uint8`，减到负数时回绕；访问图像前没有检查 x/y 范围。黑色人工边框不能代替访问保护。 | 使用有符号坐标，在每次读像素前检查范围；设置点数组容量和最大步数保护。 |
| P0 | `image.c:592–621` | 没找到起点时不刷新边界，但后面仍计算中线，可能输出上帧的旧路径。找到起点也不代表每一行边界都有效。 | 每帧重置有效标记；逐行区分真实、补出和缺失边界；失败必须发送无效状态，主控按持续失效时间减速/停车。 |
| P0 | `十字补线和最小二乘法.c:101–120` | `uint8 i` 遍历最大可达 360 的点数，超过 255 后可能回绕不退出；同时无条件访问 `i+7`，读到有效点数之外。 | 索引用 `uint16_t`/`size_t`；循环保证 `i+7 < count`，并限制 count 不超过容量。 |
| P1 | `image.c:361` | `my_abs(a-b < 2)` 实际对布尔值取绝对值；缺少右括号和外侧 `<2`，会误判左右边界相遇。 | 改成 `my_abs(a-b) < 2`。 |
| P1 | `image.c:104–105` | 最大灰度搜索错误地检查 `HistGram[MinValue]`；MinValue 是 uint8，`MinValue<256` 恒成立。后续计算未保护空前景/空背景。 | 最大值检查 MaxValue 对应的频数；索引用至少 16 位；处理零像素、单灰度和零分母。 |
| P1 | `十字补线和最小二乘法.c:72–73` | `(float)(xsum/num)` 是先整数除法再转浮点，截距会丢掉小数。 | 改为 `(float)xsum/num`、`(float)ysum/num`。 |
| P1 | `十字补线和最小二乘法.c:132–152` | 起点先存入 uint8 再限幅，负值已回绕；拟合结果先写入 uint8 再限幅，负值/超范围浮点转换不可靠。 | 在有符号/浮点临时变量中完成计算和限幅，再转换到目标类型；检查区间有效且至少两个点。 |
| P1 | `十字补线和最小二乘法.c:17–34` | 左右边界共用一个静态历史斜率，无效拟合可能混用另一侧历史值。 | 拟合显式返回成功/失败，左右历史值分别保存在各自的跟踪状态中。 |
| P1 | `image.c:445–495` | 每行只接受严格依次递减的行号；追踪中若跳过一行，后续更高行也可能不再被提取。缺失行还会保留默认边框。 | 按有效点的 y 分组提取各行边界，并保留有效性；禁止把默认图像边框当真实赛道。 |
| P2 | `image.c:506–539` | 滤波直接修改输入，后处理像素使用前面已改过的邻居，结果依赖扫描顺序；不是标准使用固定输入的形态学实现。 | 使用独立输出缓冲或固件内置处理；对比有无滤波，避免把薄黑边抹掉。 |
| P2 | `image.c:371`、`595–626` | 每帧和循环内 printf、逐点画屏会增加耗时。 | 调试时限频显示/日志；比赛运行关闭图像传输与逐点显示，统计耗时和丢帧。 |

另有集成问题：`image_process()` 使用了未提供的 `mt9v03x_image` 和 IPS154 函数；C 文件缺少 printf 的声明。辅助 C 文件未包含类型头和函数声明，也没有接入 `image_process()` 的调用链。当前是算法片段，不是能直接编译的完整工程。

更换分辨率不能只改宏：大量像素索引和坐标是 uint8。宽度改为 320 后，这些循环可能回绕；全部类型、数组大小和缓冲步长必须一起检查。`Get_image()` 的压缩选项也不能单独改为 2，否则只填小块目标区域而后续仍按旧尺寸处理。

## 推荐的首版架构

GC2093 → K230D 灰度采集/区域分割 → 左右边界及路径特征 → UART → F407 速度与转向闭环 → 电机。

1. 先用 192×120 灰度图。该宽度是 16 像素对齐值，避免直接沿用 188 带来的步长差异。以图像对象报告的实际尺寸/步长为准；需要分辨细黑边时再评估 320×240。注意低分辨率输出并不意味着摄像头采集和 ISP 延迟自动降低。
2. 先比较两个方案：修复后的八邻域追边；以及下部区域的 6–10 条横向窄带检测。后者可通过内置区域/色块函数提取候选点，结合上一帧位置、边界连续性和白色车道约束选左右边界。两者用真实赛道数据比较耗时和丢线率，再确定主方案。
3. 边界匹配只取面向车道的内侧边缘，避免把 5cm 黑色块的外侧轮廓算成车道边。不能把整幅图中的所有黑色区域一起做一次直线拟合，否则左右边界、终点虚线、阴影可能混在一起。
4. 输出近处横向偏差、远处方向、弯曲程度、置信度和逐帧有效标记。未标定透视前，“弯曲程度”只能作为图像特征，不能声称是单位为 1/m 的真实曲率。需要物理预瞄距离时再标定镜头、安装姿态和平面映射。
5. 随速度增大提高预瞄距离，急弯/置信度低时降低目标速度。示例：1.3m/s 时，80ms 延迟对应约 10.4cm 的前进距离；减少画面陈旧程度比单纯提高分辨率更关键。
6. 单侧失线时，可用已标定的“每行车道宽度”短时估计中线，并明确降低置信度；不能用全图固定像素宽度，更不能无限沿用上帧路径。

十字补线目前只作学习示例。图示闭合多边形赛道更需要锐角检测、前方可行区域判断和减速控制。起终点虚线应采用独立检测与一圈状态机，排除起步时立即误判终点；必要时结合编码器里程和赛道转弯顺序，不靠单帧黑线直接停车。

## 通信与运行目标

- UART2 使用 GPIO11/12（按功能引脚核对，不能混淆40Pin物理排针编号），115200、8N1、3.3V电平、TX/RX交叉并共地。
- 协议携带帧序号、状态、偏差、方向、弯曲程度、置信度、处理耗时和校验。定长约16–24字节即可；双方共同固定量纲与符号方向。
- 115200/8N1 理论有效负载约11520字节/秒。188×120的8位图像至少22560字节，传一帧约1.96秒；16字节结果包约1.39毫秒。因此图像处理放在K230D，F407只接收路径结果。
- 每次处理完整帧再发送结果；只有序号更新且校验正确的结果才视为新帧。MCU记录本地接收时间，结合视觉报告的处理耗时判断数据陈旧程度；不同板子的时钟不能未经同步直接相减。
- 首版实测有效更新目标50Hz以上，F407控制环目标200Hz；这些是目标，不是已验证性能。记录帧间隔、处理耗时、最长延迟和异常帧。
- 曝光/增益按当前固件的GC2093支持接口设置并实测。先确定最暗场景也能区分黑白，再缩短曝光减轻运动模糊。不要照搬其他平台的摄像头API。
- 摄像头完成中断只设置标志或交付帧缓冲；不要按 `image.h` 中的建议直接在中断内运行整套处理。

## 从哪里开始

1. 视觉队员在板上跑官方灰度采集，固定实际安装姿态，采集直道、左右转角、锐角、终点、阴影、单侧失线和完全看不到边界的样本；覆盖不同光照与行进方向。
2. 离线回放样本，修复上述P0/P1问题或完成基于内置函数的等价处理，核对边界叠加、置信度和锐角减速标志。没有实车样本前不承诺算法已经适配。
3. 用户在F407端实现包解析、序号/CRC检查及失效降速/停车，先用模拟结果验证；随后连接视觉模块测端到端延迟。
4. 低速验证连续完赛，然后逐步提速；记录每次出界前的原图和结果，不用单张图的效果代替整圈测试。
