# 任务文件与交接

版本：v1.0。日期：2026-10-25（北京时间）。维护：00制定范围，执行对话维护本任务结果。
依据：[协作标准](../collaboration_standard.md)。当前任务索引只放[状态页](../project_status.md)，本目录不再维护另一张看板。

## 什么时候建任务文件

跨轮、跨对话、有外部依赖、改变接口或需要独立验收时，建立`<ID>.md`。一次简单修正可直接在模块记录留证。保留已有任务ID；R1/R2/R3等已存在文档可继续原路径，状态页给链接即可。

同一任务单包含目标和结果，不另复制“任务版／交接版／最终版”。任务单链接规格和证据，不抄全份协议、引脚或日志。文件不在同一worktree或设备时，交接说明如何获得它；不能假设改完立即出现在另一个checkout。

## 完整任务Prompt模板

将实际内容填完，整段发给目标对话即可独立执行。占位项不得当成已授权任务。

```text
任务ID／目标对话／责任角色：
任务文件：
项目目录／来源分支／完整HEAD／未提交改动：
背景与当前已确认事实：
待实测与未知信息分别是什么：
读取材料：AGENTS、协作标准、状态页、本任务、所需模块规格和证据。
本次目标与交付文件：
允许修改范围／需保留的已有成果：
依赖与执行顺序：
验收标准：分别写资料、构建/模型、板级/实物、整车；没有条件的项目明确待验。
本次实际授权：本地修改和适用检查；远端、跨聊天、板卡动作按主控本次指令列明。
执行要求：保留共享修改；先核对版本；写入/构建/分支/硬件按协作标准协调。
完成回写：在同一任务文件记录变化、验证证据、限制、版本位置与下一步。
```

任务从主控明确请求开始；任务文件保存上下文，不自行扩展权限。清晰任务直接执行，尚未确认的重大设计选择先按项目技能处理。

## 推荐任务单结构

```markdown
# <ID>：<目标>
日期／主状态／负责角色／执行对话：
依据及主控本次要求：
## 已确认事实与待确认项
## 目标、可改范围与交付
## 依赖、步骤和验收
## 本次授权
## 执行结果
- 实际改动与文件：
- 检查日期、方法、版本、结果及原证据链接：
- 实物结果与主控体验：
- 未完成、阻塞和一个下一步：
## 接续位置
目录／分支／完整HEAD／本地未提交：
上传与设备同步：仅填写实际结果。
```

任务单中的“完成”表示所列范围完成。比如“软件交付完成，实物待验”不能变成“整车通过”。

## 收工后的短回报

```text
<ID>已回写：<任务文件绝对路径>
完成：……
验证：……；待实测：……
接续：目录／分支／HEAD；有无未提交／未上传项
阻塞与下一步：……
```

主控向00提供任务ID或文件路径，00自行读原证据；只有新口头事实才补充说明。后续需要转交时，00生成包含全部最新约束的完整Prompt。默认不自动发送跨聊天消息。

可直接使用的实例：[ORG-01](ORG-01.md)为协作体系整理，[ORG-02](ORG-02.md)为后续明确授权的物理目录迁移，包含构建／测试和二进制等价验证。
