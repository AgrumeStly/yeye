# 任务定义、执行与人工验收

2026-11-19；维护：总管。一个可验收成果一项任务；同一任务保存定义、结果、验收和接续，不复制任务版／交接版／最终版。索引仅维护在[全局状态](../project_status.md)。

## 命名与状态

保留原文件路径。旧ID有歧义时使用状态页登记的完整标识，不使用裸I-03／I-04。新任务采用`TASK-YYYYMMDD-NN-topic.md`，总管查索引后分配当日未使用编号；重试、退回和换聊沿用原ID。

状态：待核实／未开始／进行中／待主控验收／已验收／已关闭。阻塞单列；关闭必须记录停止／替代依据，不得代替完成。只有主控明确通过才标已验收，且注明接受范围；原对话审核不算人工验收。

## 统一结构

```markdown
# 唯一标识：成果目标
## 当前摘要
阶段／状态／负责角色／执行对话／更新时间：
已确认结果／阻塞与限制／唯一下一步：
## 任务定义
目标／可改与不可改范围／依赖和必要读取材料：
比赛条款与评分项／预期作用／验证指标：
交付文件／验收标准（资料、软件、板级、整车分别写）：
授权（含本地提交范围；上传另列）／检查范围／结束条件：
## 执行结果
实际改动／方法、日期、版本和证据链接／本地提交范围与检查、待验状态：
未完成项／限制：
## 主控验收
日期／主控原话／通过或退回／接受范围／证据：
## 接续信息
目录／分支／完整HEAD与交付提交号（本次新提交号在最终回报给出，避免循环提交）／未提交和未上传项／设备程序版本：
已有适用检查／恢复步骤／唯一下一步：
## 历史记录（原文保留，仅作来源）
原日期、失败、授权及旧Prompt；不得冒充当前指令。
```

新任务各栏必须填具体内容，未知标待核实。旧任务历史中的详细定义、量化指标和路径保留有效来源，总管恢复前把适用缺口提升到当前区，不要求执行者重新裁决目标。迁移本身不恢复原实现授权。

## 交接与更新

总管定义任务，主控转交；执行对话核对现场后执行。实质进展、阻塞、正常收工或交付时更新当前区，不每轮重写长总结。上下文过长换聊时给同一任务路径，继承证据和一个下一步。

执行交付回报只需：任务路径、完成范围、验证与待验、分支及完整交付提交号、剩余未提交／未上传项、阻塞及下一步。主控验收后把路径和新的通过／退回反馈交给总管；总管读取文件更新摘要。没有条件的实物项明确待验，禁止以模型代替。

执行对话完成可交付改动及适用检查后，默认按明确路径或改动块做本地提交，提交信息使用`<完整任务ID>: <改动说明>`，无需逐次确认；主控明确暂不提交或共享修改无法安全分离时如实记录原因及剩余范围。提交不改变人工验收状态，上传仍需主控明确要求。完整流程以[协作标准](../collaboration_standard.md#git-本地提交与版本交接)为准。

## 选择检查与结束

文档整理检查路径、链接和一致性；视觉改动检查相关真实样本及受影响分支，实时改动才核实板上时序；控制改动检查相关逻辑及受影响目标；协议／驱动查受影响两端。相同适用代码、配置、输入及环境复用已有证据。新复测说明新增改动或疑点，预定检查及交付满足后结束。实车按AGENTS的一次双轮悬空、一次上道流程，保留KEY与故障保护。
