# 视觉 → 主控：结果包协议 v1 草案

制定日期2026-10-12。主控代码已按本草案实现，视觉确认量纲与发送方式后再冻结；硬件确认电平、共地与引脚。正式共同接口后续只保留一份，本文件目前为主控实现配套草案。

## 字节布局

建议UART 115200、8N1、3.3V逻辑电平，TX/RX交叉、共地。固定20字节，不传整幅图像。多字节字段均小端，无浮点，无文本换行。

| 偏移 | 长度 | 字段 | 含义 |
| --- | --- | --- | --- |
| 0 | 2 | 帧头 | A5 5A |
| 2 | 1 | version | 固定1 |
| 3 | 1 | type | 1路径；2命令 |
| 4 | 1 | payload_length | 固定12 |
| 5 | 1 | sequence | 每种type独立计数，0..255循环 |
| 6 | 1 | flags | bit0路径有效，bit1终点候选；其他位0 |
| 7 | 1 | confidence | 0..100，视觉质量分，不宣称统计概率 |
| 8 | 2 | error | int16，-1000..1000，右为正。目标中线相对图像中心的偏差 / 图像半宽 ×1000，限幅 |
| 10 | 2 | heading | int16，-9000..9000，单位0.01度，右为正；当前控制未使用 |
| 12 | 2 | bend | uint16，0..1000，视觉定义的弯道强度，非物理曲率；>500演示降低基础请求 |
| 14 | 2 | processing_ms | uint16，0..1000，本帧处理耗时；超过100ms不能用于启动/保持运行 |
| 16 | 1 | command | 路径包固定0；命令包1启动、2停止、3状态查询 |
| 17 | 1 | reserved | 固定0 |
| 18 | 2 | crc16 | 对0..17字节计算CRC；低字节先发 |

CRC-16/CCITT-FALSE：poly0x1021、init0xFFFF、refin/refout=false、xorout0。标准校验向量ASCII `123456789` 得0x29B1。

命令包除offset16的command外，offset6..17均为0。置信度、方向和弯道特征的算法定义由视觉与主控确认；字段暂未使用也不能改变布局。

## 主控接收行为

- 逐字节滑窗解析，处理分包、连包、噪声、截断和错误CRC；格式错误包不更新路径时间。
- 每个type只接受向前1..127的序号增量；重复/倒退包不刷新数据。视觉不可在短时间内跳过超过127号。
- 一个type静默≥200ms后允许重建序号基线，用于板卡重启；车辆仍需新启动命令。本协议不抵御恶意重放。
- 合法STOP包始终停机，重复或旧STOP也生效；新STOP序号阻止之前延迟到达的START重新启动。
- START仅在已有有效路径、置信度≥40、处理耗时≤100ms、本地路径接收年龄<200ms时成功。
- RUNNING收到新无效/低质量路径立即FAULT；没有新鲜路径达到200ms则FAULT，左右请求归零。恢复数据不自动启动。
- STATUS当前仅解析，无回包或语音应答；终点候选仅记录，不自动认定跑完一圈。

200ms、100ms、40及转向比例均为待实测参数，不能据此认定实车已停稳。processing_ms不含完整采集/排队延迟，端到端延迟需上板实测。

## 示例与视觉交付

有效直道路径，seq1、置信度80、处理20ms：

```text
A5 5A 01 01 0C 01 01 50 00 00 00 00 00 00 14 00 00 00 92 01
```

启动命令seq1：

```text
A5 5A 01 02 0C 01 00 00 00 00 00 00 00 00 00 00 01 00 4D 12
```

停止命令seq2：

```text
A5 5A 01 02 0C 02 00 00 00 00 00 00 00 00 00 00 02 00 BB 88
```

视觉参考 [Python编码器](../tools/protocol_example.py)。电脑运行只输出十六进制和.bin文件，不向串口发启动命令；CanMV发送接口由视觉按固件适配。丢线仍发送新序号的无效包，避免无限复用旧路径。

建议路径约50Hz，命令仅在事件发生时发；这些是目标，尚未板上验证。先用模拟样例核对字节，再连接真实UART。

## 2026-11-09：独立LowSpeedLap试跑v2（不改变上述v1）

依据主控在[I-02低速一圈任务](../../project_planning/tasks/I-02-LOW-SPEED-LAP.md)确认新增独立轻量试跑目标。局部二维推荐转向量不等同固定y120偏差，因此使用**version=2**。原v1解析器／封包器及HardwareBench行为不变，双方错接版本时不能取得运行许可。v2目前为本地开发接口，实体UART／板上性能／连续一圈均待验；不是已经冻结的全队比赛接口。

帧头、20字节长度、小端、type1路径／type2命令、每type独立sequence及CRC16范围与算法沿用v1。v2字段差异如下，未列字段保持原布局与范围：

| 偏移 | v2含义 | 允许值与处理 |
| --- | --- | --- |
| 2 | version | 必须2，原v1解析器拒绝 |
| 6 | flags | bit0候选有效；bit2=120ms内无当前支持的短历史；bit3=当前单边关联；bit2／3互斥；bit1及其它位0。不定义终点自动停车 |
| 8..9 | steering | int16 -1000..1000，右正，为L1局部推荐模型产生的归一化转向请求；不是像素偏差、地面航向或标定曲率 |
| 10..11 | source_age_ms | uint16 0..1000，当前观测为snapshot软件调用开始至封包的年龄；历史为最后有当前支持的模型年龄加本次取图／处理年龄，不能用新空白帧刷新。SD模式不能作实时源；不再表示v1 heading。STM32用arrival减该值及2ms名义占线时间建立路径时间；未知年龄不能有效 |
| 12..13 | bend | uint16 0..1000，L1开发级降速风险量；由当前steering和转角模型生成，不是物理曲率或比赛评分值 |

历史包的发送及接收端期限均为最后支持证据起120ms；新空白帧不能延长这段期限。当前观测仍按含报告年龄的200ms接收保护，发送端当前源年龄<150ms。

置信度是开发几何质量量，非统计概率；目前双边70、单边45、短历史40，必须>=40才可保持运行。处理<=100ms，发送端源年龄<150ms，接收端含报告年龄的路径时限<200ms，且接收环积压>=100ms拒绝。新无效包立即锁故障，坏CRC／错版本不刷新路径，恢复数据不自启。单边与历史可供已经运行的低速候选受限延续，但**只能当前双边启动**。这些均为队内保护初值，板上实测前不放宽以掩盖性能问题。

命令包所有非command字段仍为0。STOP（command2）在重复／旧序号／积压时仍优先生效；没有自动回START。此独立目标不接受远程START，使用车载KEY（WKUP/PA0）长按1—3秒松开。两次逐轮校准仍为500ms、<=50%；运行KEY立即撤驱动。原始USART错误／接收溢出、编码器连续性／反向／超速／有运动目标却300ms无反馈均锁故障；内轮目标为0可以无脉冲，恢复正目标后重新计时。

当前速度开发初值40RPM，双轮分别0..60RPM、PWM0..50%，右转左轮较快，弯中降速，单边／历史再降速；仅前进差速，不新增倒车。停止为原00撤驱动／滑行，不能称制动距离已验或轮子立即停稳。LowSpeedLap为3秒联调，LowSpeedLapTrack为最长300000ms场地候选，均不判圈、不自动终点停车。单次5分钟上限是故障兜底，不等于已在5分钟内完成比赛。

实现：`Drivers_Custom/Communication/lap_link.c`、`lap_uart.c`及`App/Motion/lap_motion.c`；视觉`vision/src/lap_protocol.py`。本次不占用v1保留位、不改变v1 error／heading语义，不直接把演示120／80当RPM。硬件及验收入口见[试跑说明](low_speed_lap.md)。

## 2026-11-18：独立StraightAssist直道开发v3

本地授权与范围见[I-03](../../project_planning/tasks/I-03-STRAIGHT-ASSIST.md)：主控现场明确要求同时编写视觉和控制直道程序。v3为本任务两端配对的开发接口，未替换已冻结协议或宣称全队接口验收。v1／v2目标保持原版本；StraightAssist编译时只接受version=3，错配不会获得路径许可，已有RUN按原断流保护停车。

物理20字节、CRC、两type独立序号、source_age_ms、STOP优先、人工KEY启动、处理100ms／当前源年龄200ms接收监督沿用v2。发送端仍要求处理<=100ms、源年龄<150ms，不发START。v3差异：

- version=3；flags只使用bit0表示当前双边直道有效，单边／历史不能续跑。
- steering为int16 -1000..1000，右正；是直道当前双边的横向位置与方向代理量组合误差，不是直接差速比例、实际航向角或厘米。
- bend必须0，直道包不携带弯道续跑许可；无法确认直道、超出微调范围或丢失当前观测时，发新序号无效包，接收端立即锁故障。
- 置信度80为启发式开发质量量；至少连续3帧且跨80ms才能有效。实际帧率／延迟未测前不视为通过。

接收端进一步低通、死区／滞回及变化率限制，再把共同巡航RPM分配成左右小幅差速，最后分别由真实编码器PI输出PWM。共同巡航候选40..100RPM、默认80，左右目标35.2..112RPM、差速比例不超过±12%，PWM仍0..50%。单次默认2000ms、最多3000ms。以上是队内研发参数，不是已验证的道路速度／安全距离，正式整圈仍须另行集成与验收。

视觉封包源为`vision/src/straight_protocol.py`，默认预览与驱动许可合并文件由`vision/tools/prepare_straight_bundle.py`产生；不会覆盖板上main.py。场地操作见[straight_assist.md](straight_assist.md)。


## 2026-11-18：独立RightAngle首弯开发v4

[I-04](../../project_planning/tasks/I-04-RIGHT-ANGLE.md)两端配对的开发接口，version=4，20字节布局／CRC／序号及STOP优先沿用v2，旧v1／v2／v3语义不变。只有RightAngle编译目标接纳v4；不发START，由车载KEY人工启动。

- flags bit0为候选有效，bit3为当前关联单侧，禁止bit2历史续跑；只有当前双侧可启动地面循迹。置信度双侧75、单侧45是启发式质量量，不是概率。
- steering=-1000..1000、右正，来自当前直道或90度右弯的局部前视方向代理量；bend=0..1000为提前降速风险，不是标定角度／曲率。直道32、弯道56代理单位前视，不能把代理单位当实测厘米。
- 初始／失线重获须3帧且跨80ms。单侧仅在已确认前方90度双侧后，当前同一边界折角两臂有支持、路径关联且有白色中线时开放，最多2秒，强制bend=1000。空白、历史及不能关联的单直带无效。
- 双侧发送源年龄<150ms、接收含年龄与2ms占线监督<200ms；单侧发送年龄<120ms，接收含占线仍须<120ms。处理<=100ms，积压>=100ms拒绝。STM32独立监督最后bend>=200的有效双侧起2秒，新的单侧包不能刷新期限。
- 地面默认60RPM接近、12秒、PWM<=50%；满风险平均35RPM、差速比例最多100%，内轮允许零、全弯稳态外轮70RPM、过渡不超过90RPM。正目标仍受300ms无反馈监督；限时撤驱动不代表立即停稳。

同日R2（0x02120011）替代R1的逐轮启动流程，线上v4格式不变：复用已实跑确认映射，第一次KEY为双轮60RPM／1000ms悬空闭环测试。PATH无效／断源不影响该受限测试，STOP仍随时生效；编码器／方向／超速／KEY／硬件保护不变。完整双轮反馈通过后，下一次KEY才按当前双侧许可启动地面循迹。测试中断不能解锁地面，测试完成不自动上道；缺路径时拒绝地面启动并记原因。v1／v2／v3行为不变。

源：vision/src/right_angle_route.py、right_angle_protocol.py及control/App/Motion/lap_motion.c。操作和实测边界见[right_angle.md](right_angle.md)，本地检查不替代板上时序和动力过弯。

| PATH flags | v5含义 | 启动／续行 |
| --- | --- | --- |
| 1 | 当前双侧支持 | 可人工启动 |
| 9（bit0＋bit3） | 当前左纵＋前横L直接确认，缺失右边／圆弧为预测 | 置信度至少60、bend=1000、右转请求，允许独立人工启动；不等旧双侧租期 |

## 2026-11-24：StraightVoice 脱机语音直道 v6

固件标识为 0x02120004，与 [K230 v6 main.py](straight_voice.md) 配对。UART2 115200／8N1，帧为 20 字节，CRC 和独立 PATH／CMD 序号沿用既有格式。v6 PATH 沿用 v3 的当前双边、零 bend、处理和年龄限制。

- K230 命中 Go 后，取下一张图。若有当前双边许可，先发送该 PATH，再发一次 CMD START。START 的 byte 8 为该 PATH 的序号，其余 CMD 保留字段仍为 0。STM32 核对该序号等于最新已接受的 PATH，START 最后字节的到达时间距 PATH 不超过 30 ms。接收积压达 100 ms 或路径源年龄达 200 ms 时拒绝使用。指令只检查一次。
- START 须为待机、KEY 松开、近 500 ms 双轮无编码器位移且采样有效。接受后使用原直道 PI、默认 80 RPM，运行不超过 2000 ms 并保留 50% PWM 上限。KEY 急停、失线、断流、反馈、硬件和看门狗继续监督。
- STOP 的字段格式沿用既有命令，优先于 CMD 年龄和序号检查。语音停止记录为 VOICE_STOP（12）。STATUS 仅解析，接口没有执行回执。Go 超时退出或已停车不会因 PATH 恢复而重新起步。
- 冷启动等待第一帧通过版本、CRC、字段和接收年龄校验的 PATH 前，UART 错误只清空残字节和解析状态，仍保留错误计数且保持零输出。第一帧 PATH 到达后，即使当时没有有效直道许可，后续 UART 传输错误也会锁故障。
